PR.txt - Relatório do Projeto EW2026 - Aferição

O dataset fornecido (dataset_reparacoes.json) estava estruturado como um objeto JSON raiz com uma chave "reparacoes" contendo o array de documentos. Esta estrutura impedia a importação direta no MongoDB, uma vez que o mongoimport interpretava o objeto raiz como um único documento. Para resolver o problema, foi criado o script conversor.py que extrai o array interior e gera um novo ficheiro repairs.json pronto a importar.

A persistência de dados é feita em MongoDB, numa base de dados chamada autoRepair com uma coleção chamada repairs. A importação dos dados pode ser feita de duas formas: manualmente, correndo o conversor.py, copiando o ficheiro gerado para o container com docker cp e executando o mongoimport; ou automaticamente através do Docker Compose, onde o Dockerfile.mongo copia o ficheiro repairs.json e o script import.sh para a pasta /docker-entrypoint-initdb.d/, que é executada automaticamente pelo MongoDB na primeira inicialização do container.

Para responder às questões de análise do dataset, foram desenvolvidas cinco queries em MongoDB, guardadas no ficheiro queries.txt.

A solução é composta por três serviços orquestrados via Docker Compose: o MongoDB na porta 27017, a API de dados na porta 16025, e a interface web na porta 16026. A API de dados, desenvolvida em Node.js com Express e Mongoose, responde às rotas GET /repairs para listar todos os registos, GET /repairs/:id para obter um registo por identificador, GET /repairs?ano=YYYY e GET /repairs?marca=VRUM para filtrar por ano e marca respetivamente, GET /repairs/matriculas para obter a lista de matrículas sem repetições ordenada alfabeticamente, GET /repairs/interv para obter a lista de intervenções únicas ordenada por código, POST /repairs para inserir um novo registo, e DELETE /repairs/:id para eliminar um registo. As rotas /matriculas e /interv são declaradas antes de /:id no Express para evitar que sejam interpretadas como identificadores.

A interface web, também desenvolvida em Node.js com Express, usa o motor de templates Pug para renderizar as páginas e a biblioteca axios para comunicar com a API de dados. A página principal mostra uma tabela com todos os registos, onde o identificador é um link para a página do registo e a marca é um link para a página da marca. A distinção entre uma rota de identificador e uma rota de marca é feita verificando se o parâmetro é um ObjectId válido do MongoDB com mongoose.Types.ObjectId.isValid(). A página de cada reparação mostra todos os dados do cliente, da viatura e a lista de intervenções. A página de cada marca mostra os modelos únicos que passaram pela oficina e uma tabela com todas as reparações dessa marca.

Para executar a aplicação, é necessário ter o Docker instalado. Na raiz do repositório, basta correr o comando "docker compose up --build" e aguardar que os três serviços iniciem. O MongoDB importa os dados automaticamente na primeira execução. Depois disso, a interface fica acessível em http://localhost:16026 e a API em http://localhost:16025/repairs. Para parar os serviços, usa-se "docker compose down". Para reconstruir as imagens após alterações ao código, volta a correr "docker compose up --build".
